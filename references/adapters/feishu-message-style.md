# 飞书输出：会中轻卡片

## 目标

让用户在会议中扫一眼就能知道“Agent 看见了什么、我现在能做什么”，而不是阅读一份小报告。

默认使用 `lark-cli im +messages-send --markdown`。这是静态飞书图文消息，已经足够形成卡片感；没有按钮或表单需求时，不使用复杂交互卡片。

## 标题类别

每条只选一个最贴近现场的标题：

- `### ⚠️ 这里值得你打断一下`
- `### 🔄 这和你之前定的不一致`
- `### 👀 我看到一个风险`
- `### 💡 这里可能有个机会`

标题是给用户的，不显示 `ADVICE`、`OBS_EVIDENCE`、`NEED_CONFIRMATION` 等后台标签。

## 正文

通常只保留两块：

```markdown
### ⚠️ 这里值得你打断一下

**我怎么看**
一句到两句判断，必要时自然连接用户过去的决定。

**你现在可以怎么做**
给一个可直接说出口的问题、动作或选择。
```

确有关键不确定性时追加：

```markdown
**我还不确定**
只写会改变建议方向的那个不确定项。
```

不要增加“会议发生了什么”板块复述用户刚听见的内容；现场事实只作为判断所需的最小背景。

## 长度与节奏

- 一张卡只承载一个核心判断；紧密相关的两个点可以合并。
- 通常控制在用户一屏内，先删背景复述，再删次要依据，不删判断和动作。
- 同一判断没有新证据不重复发。
- 无价值批次不发“保持安静”卡。

## 就位卡

```markdown
### 小T已入会

我正在听。值得介入时会私信你，没有增量时保持安静。

今天如果有特别希望我盯住的问题，回一句即可；不回我也会继续。
```

## 会后私信

飞书只发一句结束回执和 Agent 聊天入口，不在私信里重复完整总结。若本场存在会后深读队列，明确还在继续分析：

```markdown
### 会议已结束

监听已停止。这场内容需要继续关联你的历史材料，我正在做会后分析；完成后会在当前 Agent 聊天给你确认卡，再决定是否更新 OBS。
```

只有 `writeback-candidate.md` 已生成且确认卡已展示时，才能改成“会后确认已准备好”。
