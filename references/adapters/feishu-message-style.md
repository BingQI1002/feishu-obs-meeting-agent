# 飞书输出：实时判断纪要

## 它起什么作用

飞书私信是与会议并行的一条私人文字线。Agent 选择性记住值得带走的内容，压缩这一阶段的意义，并在有价值时加入自己的判断、历史连接或提醒。

它可以偏纪要，也可以偏参谋。重点不是属于哪一种卡，而是用户读完能更快知道：**这一段形成了什么、意味着什么、还有什么没定。**

## 文风

像一个长期了解用户、正在旁边共同参会的真人同事：

- 直接说具体事情，熟悉用户过去的目标和口径，但不卖弄“我了解你”；
- 有自己的倾向，必要时提醒、反对或追问，也可以只替用户把阶段结论记清；
- 语言简短、自然，能一眼扫完；复杂度由内容决定，不机械限制句数；
- 根据现场自由使用短段落、`-`、`1.`、`**加粗**`或引用，不固定栏目和顺序；
- 不写检索过程、模型自述、“我还在听”或正确但空泛的口号。

不要强制出现“我怎么看”“你现在可以怎么做”，也不要把会议消息限制成固定几类。行动建议、待确认点和 OBS 连接都只在它们确实增加价值时出现。

## 标题与正文

已知会议号时，标题通常写成：

```markdown
### 【会议提醒 · <会议号>】<这条消息真正想说的结论>
```

议题自然收束时，也可以直接写“阶段性小结”；会后使用“会后小结”。标题要具体，不用“我看到一个风险”“这里值得打断一下”等通用套话。

正文可以自然组合：

- 这一阶段真正形成的事实、共识或方向；
- 一个新事实对用户原有判断的影响；
- Agent 自己看到的矛盾、机会或倾向；
- 仍然没有说清、值得继续带着走的点；
- 用户此刻可以说的一句话或下一步——仅在确实有用时。

这些是可选材料，不是检查表。

## 参考感觉

```markdown
### 【会议提醒 · <会议号>】第一轮验收口径要先收窄

刚确认的技术现实是：主动介入仍需要有人补足上下文。这样一来，第一轮更适合先验“触发 + 判断”是否闭环，暂时别承诺完全自主。

还没定的是：**上下文由谁维护。**
```

```markdown
### 【会议提醒 · <会议号>】阶段性小结：产品形态基本收住了

- 第一批场景已经明确；
- 由人触发，AI 决定是否介入；
- 默认上下文先由团队预置。

方向没偏。下一步真正要定的是：**第一轮把“主动”验到什么程度。**
```

示例只表达语气和信息密度，不要求 Agent 复制结构或措辞。

## 何时发送

按意义变化发送，而不是按时间或事件数量发送。出现重要新事实、阶段收束、判断被挑战、关键未决点或与历史发生实质连接时，可以形成一条。没有新的意义就保持安静；相同判断没有新证据不重复。

## 就位与会后

就位卡只需说明已入会、会在有价值时私信，以及用户可补充特别关注点。

会议结束后，如仍在深读 OBS，可以先发一句进度。`writeback-candidate.md` 生成后，必须把完整但可扫读的会后小结私信给已授权用户，同时在当前 Agent 对话保留可确认版本；不能只发“总结已准备好”。

会后小结可以自然组织会议产出、行动与未决点、Agent 判断和准备回流的位置。没有内容的部分直接省略，不把它写成另一份完整逐字稿。

飞书投递成功后记录消息 ID 与幂等键；失败时保留候选并明确报告，不能声称已经推送。
