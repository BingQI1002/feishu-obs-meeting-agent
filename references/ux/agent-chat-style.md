# Codex 对话：持续理解与会中交互

## 目的

飞书是选择性打断用户的私人纸条通道；Codex 会议任务是用户观察 Agent 是否仍在听、怎样理解会议以及随时补充背景的主界面。

Codex 对话不输出逐字稿，也不展示隐藏的完整思维过程。它持续呈现可核查的阶段性理解：当前议题、实质变化、Agent 判断、OBS 真正带来的连接和接下来关注什么。

## 入会后的第一段对话

机器人真实入会并启动监听后，在 Codex 对话中显示运行状态和动态对齐问询：

```markdown
### AI 正在听会 · <会议号>

我已入会，会继续听。回一句即可，不影响监听：

- 这是什么会？（自由填写）
- 你今天主要是？主导决策 / 需要发言 / 普通参与 / 主要旁听
- 有没有额外侧重？发言决策 / 项目目标 / 风险关系 / 承诺跟进 / 会后复盘

角色单选，侧重可多选，也可以直接说自己的目标；不回我也会继续。
```

这段只出现在 Codex，不发飞书。用户不回答时基于现场与 OBS 建立临时理解，继续监听。

## 持续理解怎样呈现

按会议语义推进，而不是逐条转写。以下变化通常值得在 Codex 留下一条简短更新：

- 第一个完整议题形成；
- 议题、发言人或决策对象发生变化；
- 出现新的事实、分歧、决定、承诺、风险或机会；
- OBS 证据真正改变了当前理解；
- Agent 修正了先前判断；
- 一段时间没有新结论，但需要让用户看见当前仍在持续理解什么。

自然写成一小段即可，例如：

```markdown
### AI 正在听会 · 当前讨论首轮试用

团队已从“功能能否运行”转到“先在哪场真实会议验证”。现在收敛到老肖的业务周会，但验收仍停留在纸条内容好不好；我继续关注他们是否把它落成可观察的提问、判断或行动变化。
```

更新可以说明本轮没有发飞书纸条及原因，但不要把每一次技术轮询写给用户。相同理解没有新证据时不重复；寒暄、半句话和纯流程信息不单独输出。

## 主动向用户补问

当缺口会明显影响身份映射、检索方向或判断质量时，在 Codex 对话直接问用户。典型问题包括：

- “刚才说话的是谁？”
- “这里提到的‘他’是老肖还是另一位负责人？”
- “这个缩写在你们内部具体指什么？”
- “这一段你还是主要旁听，还是接下来需要发言？”

一次只问最关键的一到两个问题，并带上当前临时理解，让用户容易纠正。提问后继续监听，不把问题作为阻塞条件，也不发到飞书。

用户没有及时回答时，用“说话人待确认”“对象暂按某项目理解”等临时标记继续。用户纠正后更新 `agent-state.md` 的人物映射和当前议题，复查近期受影响的判断；已经发出的错误纸条需要明确修正，不能静默覆盖。

## 证据边界

- 不得写“已结合 OBS”但不说明哪类历史真正改变了判断。
- 没有读取相关 OBS 时，可以只基于会议现场形成判断。
- 已读取但没有改变理解时，不把检索本身包装成价值。
- 当前理解不确定时明确说出缺口，并在值得时向用户补问。
