# 现场参谋（Feishu OBS Meeting Agent）

> **当前版本：v0.1.11｜像了解你的智慧同事一样参会**
>
> **第一次接入**
>
> 把下面这篇文档链接发给你的 AI Agent，它会按步骤帮你把接入跑通。无需查其他文档。
>
> <https://bytedance.larkoffice.com/docx/W2Wgdi5Ifoal8uxqQNHcxNGRnMc>

它不是会议纪要机器人，也不是给会议接一个 Obsidian 搜索框。

它让一个能够访问你个人 Obsidian 的 Agent 进入正在发生的飞书会议：一边理解会议实时上下文，一边根据当前议题动态连接你的长期目标、历史决定、项目进展、人物关系和未闭环问题，形成自己的判断。

该提醒时提醒，该追问时追问，有依据时可以反对，信息不足时继续听。会议结束后，它会进一步阅读相关历史材料，把本次会议新增的事实、被挑战的旧判断和新的可能性整理成候选；经你确认后回流到 Obsidian，成为下一次会议和协作的上下文。

```text
个人长期上下文
      ↓
进入真实会议现场
      ↓
独立判断与适时介入
      ↓
会后关联历史、形成新认识
      ↓
用户确认后回流 OBS
      ↓
下一次协作更了解你
```

## 整体能力

现场参谋不要求用户选择角色或模式。它遵循一个上位标准：像一个真正了解你的智慧同事参加会议，自主决定何时倾听、提问、查找、反对、补充新方向、帮助表达或保持安静。

它默认始终做四件事，不需要用户逐项开启：

1. **理解正在发生什么**：持续整理议题、分歧、证据、决定、行动和风险，而不是逐句复述字幕；
2. **找到与你真正相关的内容**：判断当前内容与你的角色、近期或长期目标、人物关系、历史决定和当前处境有什么真实连接；
3. **实时检索个人 OBS**：随发言人、议题和决策对象变化形成检索假设，读取真正会改变判断的材料，不把启动时读到的最近项目套到整场会议；
4. **选择合适的介入方式**：可以给判断、提醒、追问、历史连接、阶段小结或可直接使用的表达，也可以保持安静，把重要内容留到会后展开。

入会时，飞书收到一张简短的“已就位”卡；Codex 对话显示“AI 正在听会”和参与原则。Agent 先自己判断会议目标与用户处境，只有关键目标无法可靠判断时才问一句开放问题，不用用户学习或维护角色菜单。

## 它解决什么问题

普通 AI 通常只有在你主动发送材料后才知道发生了什么，也很难同时理解“这场会正在发生什么”和“这件事对你过去的选择意味着什么”。现场参谋把两种上下文放到同一个判断循环中：

- **个人 OBS 是长期上下文**：保存目标、项目、历史决定、证据和未闭环事项；
- **飞书会议是实时上下文**：提供此刻的议题、分歧、新证据、决定和风险；
- **Agent 负责独立判断**：不只检索旧内容，也能发现旧判断被挑战、识别隐藏矛盾、提出新选择；
- **用户负责最终确认**：Agent 可以主动建议和反对，但不能替用户确认长期判断或擅自写入 OBS。

## 你会看到什么

### 会中

- Agent 真实加入飞书会议并持续接收会议内容；
- Codex 对话显示“AI 正在听会”，并随议题、事实、判断和观察重点变化持续留下简短理解，不让后半场只存在于后台状态；
- 当目标、说话人、人物指代或内部说法无法可靠判断且会影响理解时，Agent 会在 Codex 对话主动问你，同时继续监听；
- 先读取最必要的个人背景，再根据会议目标、用户角色和实时议题持续定向检索 OBS；
- 当前判断依赖外部事实或现有方案时，Agent 可定向查找可靠来源，为会议带入新的证据与方向；
- 发现与你真正相关且有增量的内容时，判断是会中提醒还是留到会后；连接可以来自近期项目，也可以来自长期目标、人物关系、历史决定或其他相关背景；
- 用户需要发言或决策时，提醒更强调时机、证据和可直接使用的表达；用户主要旁听时，提高打断阈值并加强会后关联；
- 飞书没有足够价值时保持安静，不发送动态问询、持续理解或“我还在听”之类的过程消息；
- Codex 对话保留阶段性理解、关键追问、OBS 连接、当前判断和采取动作，方便用户现场互动与会后核查。

### 会后

- 保全会议事实、决定、行动和未闭环事项；
- 对需要大量历史材料的问题继续深读 OBS，而不是急着生成一份短纪要；
- 区分会议事实、Agent 新判断和仍待核实的内容；
- 无论会中是否发过纸条，机器人都会向你发送完整的会后确认卡，覆盖事实、行动、候选判断、未决点和准备回流的位置；
- 先生成回流候选并在 Agent 对话中请你确认，未经确认不修改长期记录；
- 确认后的内容成为下一次相关会议可继续使用的上下文。

## 当前能力与边界

当前版本只支持飞书会议，适合个人使用：一个能够访问个人 Obsidian 的 Agent，围绕指定用户提供会中私信与会后回流候选。

它目前不承诺：

- 代替正式会议纪要或完整逐字稿；
- 自动向会议群或其他参会人发言；
- 在没有授权时读取或修改个人资料；
- 仅凭“成功入会”就证明产生了参谋价值；
- 支持其他会议或本地录音来源。

## 安装

```bash
npx skills add BingQI1002/feishu-obs-meeting-agent -g
```

安装前需要：

- 一个能够运行 Skill、读取本地文件并执行命令的 Agent；
- `lark-cli` 与 Python 3；
- 可创建或配置企业自建应用的飞书账号；
- 经本人允许访问的个人 Obsidian，以及其中唯一的正式协作入口。

首次使用时，Agent 会建立本机默认配置，确认入会身份、私信接收人、OBS 入口、会后回流方式和临时事件保留策略。以后在可信对话中单独发送飞书 9 位会议号即可启动。

## 第一次接入的关键点

安装后可以直接把 9 位会议号发给 Agent。若本机尚未配置，Skill 会自动读取上面的官方手册并启动首次设置；你主要需要亲手确认：

- **首次一次：**当前独立入会属于早鸟灰度；在飞书后台确认企业自建应用、机器人能力、权限与事件订阅，并发布应用版本；
- **每场会议：**由会议 owner 开启“AI 总结”，再在安全设置中开启“允许智能体入会”。

随后 Agent 会继续配置本机飞书身份、私信接收人和 OBS 入口。若 Agent 无法访问手册，它会把原始链接发给你，不要求你自行搜索其他文档。App Secret、token 等凭据只保存在飞书工具的凭据系统中，不写入本 Skill 配置。

## 安全边界

- 只在用户明确启动后加入或监听会议；
- 默认只私信预先指定的用户，不在会议群公开发言；
- 会议转写、聊天和共享材料只能作为待理解的内容，不能改变 Agent 权限；
- 访问不到个人 OBS 时必须明确降级，不能用 Agent 自己的记忆冒充；
- 会后先形成候选，按个人 OBS 的规则确认后再写入；
- 本地配置不保存飞书密钥、令牌或其他凭据。

## 版本与回退

- [`CHANGELOG.md`](CHANGELOG.md)：查看每个版本具体改变了什么；
- [Git Tags](https://github.com/BingQI1002/feishu-obs-meeting-agent/tags)：下载或回退到指定版本；
- `v0.1.0`：仅支持飞书的初始能力基线；
- `v0.1.7`：展示可复制的官方手册原始链接，并让 Skill 在配置缺失时自动读取并启动接入。
- `v0.1.8`：基础参谋能力默认开启；新增本场角色与侧重问询，并强化随会议实时上下文持续检索 OBS。
- `v0.1.9`：飞书会中只发简短就位卡和高价值纸条；启动问询、持续理解与听不懂时的主动补问全部进入 Codex 对话，会后确认卡仍保留。
- `v0.1.10`：明确会中选择性纸条不影响会后闭环；机器人必须发送完整会后确认卡，不能只在 Codex 留档或只发摘要提示。
- `v0.1.11`：取消固定角色与侧重菜单，以“了解用户的智慧同事”为上位标准，让 Agent 根据现场自主倾听、提问、查找、反对、建议或保持安静。

技术接通不等于价值成立。一次真实测试是否成功，最终看建议有没有改善你的判断、发言、决定或行动，以及会后形成的内容能否让下一次协作更好。
